# 4x5 tab (2026-11-02)

## Goal
Vertical Reels (9:16) → 4:5 copies for the feed, without visible quality loss and with a reasonable file size.

## Decisions (with the user)
- Drop a folder (or videos). A folder is rebuilt next to it as "<folder> 4x5" with the same subfolders; each video
  becomes "<name> 4x5.mp4". A single video gets its copy next to it.
- Crop always in the middle, full width kept, never upscaled (1080×1920 → 1080×1350, 2160×3840 → 2160×2700).
  Wider than 4:5 → the sides are cut instead. Odd centre offsets go 1 px up (4:2:0 needs even offsets).
- Encoding: "Qualité (CPU)" by default = x264 CRF 17 medium; "Rapide (GPU)" = VideoToolbox q 65 (remembered).
  Measured on real Reels: x264 SSIM 0.997 at about half the size; GPU same quality, 2× faster, sometimes ~15 % bigger.
- 10-bit / HDR phone footage: 10-bit HEVC (x265 or VideoToolbox) with its colour tags, never washed-out 8-bit.
- Audio copied as is (AAC, MP3, ALAC, AC-3, E-AC-3, Opus), otherwise AAC 320k. +faststart.

## Safety
- Premiere preview/auto-save folders, hidden files and earlier "… 4x5" outputs are skipped.
- Never overwrites: an existing output is "déjà fait". Written as "… 4x5.en-cours.mp4", renamed when complete.
- Cancel stops ffmpeg, removes the partial file, the video goes back to "à convertir".

## Code
`electron/fourfive.cjs` (plan, probe parsing, crop, ffmpeg args), IPC `fourfive:*` in main, `src/pages/FourFive.jsx`
(stays mounted so a batch keeps running across tabs). Tests: `scripts/test-fourfive.mjs`, including real encodes
(centring checked with coloured bands, CPU and GPU, PCM audio, 10-bit HDR).
